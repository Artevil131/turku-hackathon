# Decisions

Every technical, mathematical or statistical choice the team has made.
Code and experiments depend only on choices listed here (AGENTS.md). A
reversed decision is not deleted: add a new entry and mark the old one
`superseded by D-NNN`.

| ID | Date | Decision | Why | Decided by |
|----|------|----------|-----|------------|

| D-002 | 2026-10-16 | Challenge: Antibiotic Efficacy Indicator by Tyks Laboratories (CONTEXT.md) | Team choice | Artem |
| D-003 | 2026-10-16 | Web in TypeScript with React + Vite. Rust is planned for some gears later, which ones not yet chosen | TS on the web; React pairs with a later Expo app | Aapo |

| D-005 | 2026-10-16 | "Continuously updated" is shown by a replay clock over the dataset; the server pushes arrivals to clients with server-sent events. | D-006 | 2026-10-16 | The API and event contract lives in `libs/utils/contract`; `apps/api` is a TypeScript dev server implementing it over the CSVs. A Rust server may replace it behind the same contract | Web work can start now without fixing the backend language | Aapo |
| D-007 | 2026-10-16 | Vitest for tests, Biome for lint and format | Vitest shares Vite; Biome is one tool for both | Aapo |
| D-008 | 2026-10-16 | Impeccable design skill installed in the repo for Claude Code and Codex (`.claude/`, `.agents/`); its engine binary is fetched on first run, not committed | Same design guidance and checks for every agent | Aapo |
| D-009 | 2026-10-16 | Units are related through two layers: patient flow (patients sampled in two units) and phenotype trail (a resistant phenotype seen in one unit, then another). How each is modelled is not decided | The team wants to model how findings in one unit inform treatment in another | Aapo |
| D-010 | 2026-10-16 | Both users served equally: the ward doctor choosing empirical treatment and the infection control team. UI in Finnish and English with a toggle | Team choice (PRODUCT.md) | Aapo |
| D-011 | 2026-10-16 | Patient flow between units: a patient's sample in unit B whose previous sample (by date) was in unit A is a move A → B, counted once per patient and dated by B's sample; all cultures count, negative ones too (`@aei/relations`) | Matches what the map already showed, now computed live; distinct patients so one frequently sampled patient does not dominate | Aapo |
| D-012 | 2026-10-16 | Phenotype trail: a patient with ESBL, MRSA, VRE or CPE found in unit A and later sampled in unit B (any result) within 90 days of the latest find counts as a carrier A → B; whether B's sample showed the phenotype again is kept as `confirmed` | Earliest warning for the receiving unit; 90 days as a plausible carriage period without reaching back years | Aapo |
| D-013 | 2026-10-16 | Flows and trails follow the view's window (four weeks, a year) as the replay clock moves, rather than whole-dataset totals | Keeps the relation layers "continuously updated" like the rest of the tool | Aapo |
| D-014 | 2026-10-16 | (carrier part superseded by D-022) Alerts without statistics (`@aei/alerts`): every CPE isolate is an alert on its sample date, and every carrier arrival (D-012) is an alert; the server pushes them as they arrive. VRE or MRSA "new in a ward", clusters, ward against hospital and trends wait for their own decisions | A single CPE is a zero-tolerance event in infection control; carriers moving between units are the earliest warning the data supports | Aapo |
| D-015 | 2026-10-16 | The demo replay starts on 2025-05-12 by default (`AEI_REPLAY_START`), three weeks before the Urology ESBL *E. coli* cluster found in experiments/0001 | The demo shows a normal ward, then an outbreak arriving; the old default (eight weeks before the data ends) contained no planted event | Aapo |
| D-016 | 2026-10-16 | Deviation detection starts from six candidate detectors taken from Artem's notes (profile rule, profile excess, phenotype excess, sampling drop, resistance shift, rising trend), run with several thresholds and scored in experiments/0002 on the planted events of 0001 by detection delay and number of other signal episodes. The final detectors and thresholds are chosen from that comparison | No time to settle methods before trying them; measuring candidates on known events lets Artem and Aapo decide from numbers | Aapo |
| D-020 | 2026-10-16 | The server runs four detectors live and raises one alert per signal episode (`@aei/detect` `liveSignals`, `@aei/alerts` `detectorAlerts`): profile excess within specimen (alpha 0.0001), phenotype excess (alpha 0.001), sampling drop (alpha 0.0001), rising trend over 22 pairs (alpha 0.001). Provisional until Artem reviews experiments/0002 | The best setting of each detector in 0002; together they caught every planted event at about 5 other episodes a year | Aapo |
| D-021 | 2026-10-16 | An MRSA or VRE isolate in a unit that had none in the previous 180 days is an alert (`@aei/alerts` `newInUnitAlerts`); silent for the first 180 days of the data. Provisional | benchmarks/planted-events asks for a sentinel on the first ICU MRSA of March 2026; 180 days fires on it (2026-03-03) at about 5 alerts a year (30 days: 25 a year) | Aapo |
| D-022 | 2026-10-16 | Carrier arrivals (D-012) are no longer pushed as alerts; they stay available per patient (`@aei/alerts` `carrierAlerts`, `@aei/relations`). Isolates of a cluster already detected are left out of the rising-trend test from the day it is detected (`liveSignals`) | Review of 2026-10-16: 320 carrier alerts in three years, 4 confirmed in the new unit, against 12 detector alerts in the demo span; and the Urology outbreak also raised false hospital-wide cefuroxime and ceftriaxone trends | Aapo |
| D-023 | 2026-10-16 | The doctor's coverage list (`@aei/coverage`): per antibiotic suited to the specimen, the share of first isolates covered over the last 365 days, at the unit if it has at least 30 known results, else its ward type, else the hospital; 95 % Wilson interval; intrinsic and no-breakpoint pairs count as not covered; untested pairs are left out and listed by organism; the unit's last 28 days returned as context only; optional sex filter. Provisional until Artem reviews | experiments/0004 (the year predicts the next 28 days better than the last 28 days) and 0005 (sex matters for urinary ciprofloxacin); 30 is the organiser's reporting floor | Aapo |
| D-024 | 2026-10-16 | Data analysis (experiments, scripts, cross-checks) is done in Python, managed by uv from the root `pyproject.toml` (numpy, pandas, scipy, statsmodels, matplotlib; pytest for tests); shared Python helpers live in `libs/utils/py/aei`. Anything the app runs stays in TypeScript in `libs/utils`, and a Python result that the app needs is ported there | Python's statistics libraries replace hand-written tests and make exploration faster; the live tool keeps one language. Experiments 0001 to 0007 stay in TypeScript | Aapo |
| D-025 | 2026-10-16 | The researcher network view uses THL's communicable disease register (cases cube, CC BY 4.0): monthly MRSA, ESBL (*E. coli*, *K. pneumoniae*), VRE and CPE cases and incidence per wellbeing services county, fetched by `scripts/fetch_thl_ttr.py` into `data/external/thl/` (git-ignored), kept apart from the synthetic dataset | The judges asked for regional to worldwide levels from open data (AUDIENCE.md); research/open-data.md ranks this the best Finnish regional source; external data never mixes with the organiser's synthetic records | Aapo |
